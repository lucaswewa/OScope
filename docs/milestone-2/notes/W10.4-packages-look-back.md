## Summary

The service serves the app, and Milestone 2 is ready to release ([spec](../phases.md#w10-4)):

- **The packages carry the app:**
  - the .deb in `/usr/share/oscope/web`;
  - the zip in `web`, beside the server, which `install.ps1` copies to `C:\Program Files\OScope\web`.
- **The server serves the app installed with it** when its configuration names none. An operator's own configuration from 0.1, kept through an upgrade as dpkg keeps a conffile changed, serves it so.
- **Their checks ask `/` for the app:** `test-deb.sh`, `test-zip.ps1` and the deployment's `smoke-test.sh`.
- **The build from source and the release workflow build the app,** with Node 24. The deployment guide installs it, through nvm, for the operator.

## How to try it

On Ubuntu 24.04, as [the deployment guide](../../deploying-on-ubuntu.md) builds and installs it, then open `http://127.0.0.1:8210/`: the app. Or, with Docker, from a release build and the built app:

```sh
npm --prefix web ci && npm --prefix web run build
cargo build --release --locked -p oscope-server
bash packaging/linux/test-deb.sh "$(bash packaging/linux/build-deb.sh target/release/oscope-server)" ubuntu:24.04
```

On Windows, the zip's check, without installing the service:

```powershell
$zip = powershell -File packaging\windows\package.ps1 -Server target\release\oscope-server.exe
powershell -ExecutionPolicy Bypass -File packaging\windows\test-zip.ps1 $zip
```

## Design notes and deviations from the plan

- **The server finds the app, rather than the packaged configurations naming it.** The spec has the service serve the app by W0.1's `[web] root`. But dpkg keeps an operator's changed `/etc/oscope/oscope.toml` through an upgrade, and the zip's `install.ps1` keeps the one in `C:\ProgramData\OScope`. A root named only in the packaged files would leave 0.1's operators without the app. The server looks where the packages put it, as it already looked for its third-party notices (W4.3).
- **The .deb built on this PC is tried in Ubuntu 24.04 alone:** its server, built under WSL's 24.04, needs 24.04's C library. The release builds on 22.04, and tries its .deb in both.
- **A first build of the server in release** is xtask's and the checks' own, in `target-perf`: the owner's release server runs from `target/release`.
