## Summary

The server keeps recipes and checks them, so that the graph editor has something to talk to ([spec](../phases.md#w7-1); [ADR-0052](../../adr/0052-recipes-over-the-api-the-pipeline-thing.md)). It is server work, which W7.2 and W7.3 draw on: the `pipeline` Thing that plan §5.4 lists, and P21 left for the editor.

- **`nodes`:** the catalogue, the stock nodes' and the extensions', each with its ports and its parameters' schema. `preview/nodes` stays, and gives the same.
- **`check`:** a recipe's faults, all at once, each with the node and the port it is at. It changes nothing, and needs no lease.
- **The library:** recipes listed, read, saved and deleted by name, in the data root. Six stock recipes come with it, which can't be changed.
- **`run`:** a recipe on a project's records, a `workspace.run` job each.
- **The generated types, and the client's wrappers.**

## What was built

- **`oscope-pipeline`:**
  - **`library.rs`:** the library, its names checked, the stock recipes and the user's; and `check`, every fault of any JSON.
  - **`recipes/`:** the stock recipes: `count-nuclei`, `false-colour`, `green`, `inverted`, `levels` and `smooth`.
  - **`Problem`** gains `node` and `port`; `plan.rs` sets them where each fault is found.
- **`oscope-api`'s `pipeline.rs`:** the `pipeline` Thing, on every server, devices or not; and its `check` let through without the lease, in `auth.rs`.
- **`web/src/api/pipeline.ts`:** the wrappers: the catalogue, `check`, the library, and `run`.

## How to try it

On the CUDA build, as W6's notes say, with `curl`:

```sh
cargo build --release -p oscope-server --features cuda
target/release/oscope-server --config configs/oscope.toml --port 8211
```

1. **The catalogue:** `curl http://127.0.0.1:8211/api/v1/pipeline/nodes`: each node, its ports and its parameters' schema.
2. **Save a recipe:**

   ```sh
   curl -X POST http://127.0.0.1:8211/api/v1/pipeline/save_recipe -H 'content-type: application/json' -d '{"name": "blur-3", "recipe": {"format": 1, "name": "Blurred by three", "inputs": [{"name": "image", "type": "image"}], "nodes": [{"id": "blur", "node": "filter.gaussian", "params": {"sigma": 3}}], "edges": [{"from": "input.image", "to": "blur.image"}], "outputs": [{"name": "image", "from": "blur.image"}]}}'
   ```

3. **List it:** `curl http://127.0.0.1:8211/api/v1/pipeline/recipes`: the stock recipes, then `blur-3`. `curl http://127.0.0.1:8211/api/v1/pipeline/recipe/blur-3` reads it.
4. **Check a broken one:** the same recipe with a node `{"id": "level", "node": "threshold.otsu"}` and an edge `{"from": "blur.image", "to": "open.mask"}` to a node `{"id": "open", "node": "morphology.open", "params": {"radius": 1}}`, posted to `pipeline/check` as `{"recipe": …}`. Then `GET` the invocation's `href`: both faults, each with its node and port.
5. **A name that would leave the library:** `{"name": "../out", …}` to `save_recipe`: refused.

On the CUDA build, by a script doing what `curl` does: the catalogue's 42 nodes; `blur-3` saved, listed after the six stock recipes, and read back. The broken recipe's faults came back at `open.mask`, *`blur.image` gives image, and `open.mask` takes mask*, and at `level.image`, *its input `image` has no edge*. `../out` was refused, *a recipe's name has 1 to 64 characters of a–z, 0–9, - and _*. And the stock `smooth`, run on an imported TIFF, made a result, *Smoothed*, its provenance naming `filter.gaussian`.

## Design notes and deviations from the plan

- **A fault's place is data:** `node` and `port` beside P21's `at`. An edge's fault is at its end, a type mismatch at the input it goes to. A cycle is one fault, at the node it starts from, as P21's tests have it, its message naming the rest.
- **`check` needs no lease** (ADR-0052): it changes nothing, so the authoriser lets it through, as it does `settings/display`. The test of every affordance that changes state now expects it.
- **`check` counts a GPU as present on a CUDA build,** rather than opening a second CUDA context to ask. No stock node needs a GPU.
- **Saving keeps a recipe with its faults,** so that the editor keeps work half made. `run` refuses one, before any job.
- **`run` is the Workspace's run for many records:** a `workspace.run` job each, so each result has P48's provenance.
- **Stock recipes are built in:** four from `ex-live-recipe`'s, as it has them, and `smooth` and `count-nuclei`, new. Those that read a reference, the flat fields, aren't among them: a server may have none.
- **The library lists names, titles and whether each is stock,** not dates: `oscope-pipeline` has no date crate, and `chrono` is due to go.
